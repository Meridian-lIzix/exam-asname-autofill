## 安装

1. **下载并解压**：[获取安装包](https://github.com/Meridian-lIzix/exam-asname-autofill/raw/refs/heads/main/exam-asname-autofill.zip)，解压到固定位置。
2. **加载扩展**：打开浏览器扩展页，启用「开发者模式」，点击「加载已解压的扩展程序」，选择解压出的 `exam-asname-autofill` 文件夹本身。
3. **登录网站**：打开 [exam.asname.cn](https://exam.asname.cn/) 并登录，页面右下角会出现助手面板。

| 浏览器 | 在地址栏输入 |
| --- | --- |
| Chrome | `chrome://extensions/` |
| Edge | `edge://extensions/` |

> [!TIP]
> 初次使用建议先[下载 JSON 题库](https://github.com/Meridian-lIzix/exam-asname-autofill/raw/refs/heads/main/question-bank/题库-2026-09-06.json)，再通过面板底部的「导入题库」加载已有答案。已有题库会自动合并，无需清空。

加载后请保留扩展所在文件夹。更新时，在扩展管理页**重新加载扩展，再刷新考试网页**。

## 使用

1. **刷新场次**：登录后点击「刷新场次」，勾选要处理的场次。列表每 30 秒自动刷新，开始前会再次核实可作答状态。
2. **调整参数**：按需设置[网页并发、AI 每组题数和并发组数](#并发与分组)。需要 AI 补答时，先完成 [AI 设置](#ai-设置)。
3. **开始处理**：点击「开始」。优先使用已知答案；测试中缺少答案的题，启用 AI 后才发送给模型。未启用 AI 或调用失败的题保留为待解答。
4. **查看结果**：处理结束后手动刷新网页查看作答，最终交卷由你完成。

> [!NOTE]
> 「作答已核验」表示网站保存了预期选项。测试不返回官方答案时，这项核验不能证明答案正确。扩展不会自动最终交卷。

点击「停止」会停止派发新任务并取消 AI 请求，已获得的答案保留；重新运行会优先复用题库。请勿在多个页面同时开始答题。

## 并发与分组

| 设置 | 默认值 | 可选范围 | 作用 |
| --- | ---: | ---: | --- |
| **网页并发** | 5 | 1～20 | 同时读取题目、保存选项和回读核验的网站请求数。 |
| **AI 题/组** | 30 | 1～100 | 每次 AI 请求最多包含的题目数。 |
| **AI 并发** | 2 | 1～10 | 同时发送给 AI 的题目组数。 |

**最多同时处理题数 = 每组题数 × AI 并发组数。** 例如 40 题/组、并发 2，最多同时处理 80 题；其余题目自动排队，一组完成后立即接续。整场题数不受这个乘积限制，网页并发也不会改变 AI 并发。

AI 两项参数修改后自动保存，运行期间不可修改。鼠标悬停或用键盘聚焦旁边的「i」，可以查看说明。

- **起步配置**：30 题/组、并发 2。
- **长题或输出不完整**：降低每组题数。
- **服务限流**：降低 AI 并发。

## AI 设置

在面板中打开「AI 设置」，配置服务并保存，允许扩展访问对应服务域名，再点击「测试 AI」。

| 配置项 | 填写说明 |
| --- | --- |
| **Base URL** | OpenAI Chat Completions 兼容服务的基础地址，保留服务要求的路径，例如 `https://api.example.com/v1`。 |
| **API Key** | 填写该服务的有效密钥；本机服务可以留空。 |
| **模型名称** | 使用该服务实际提供的模型 ID。 |
| **启用 AI 补答** | 勾选后，开始处理时才会为缺少答案的题调用 AI。 |

远程接口必须使用 HTTPS；本机 `localhost` / `127.0.0.1` 服务可以使用 HTTP。保存设置和「测试 AI」不受考试开放时间限制，也可以从扩展管理页打开设置页操作。

「测试 AI」使用**已保存配置发送 1 道固定示例题**，核对接口、返回题号和选项格式，并显示模型及耗时。测试可能产生少量调用费用，不修改考试或题库；即使所有题目都命中题库，也能单独测试 AI。

<details>
<summary><strong>数据发送与答案校验</strong></summary>

- 配置保存在本机扩展存储。密钥通过独立的扩展设置页输入，不进入网站存储或题库导出。
- 启用 AI 后，仅向所配置服务发送待解答题目的题号、题型、题干和选项，调用可能产生费用。
- 模型按题号返回 JSON，扩展校验题号、选项范围和单多选数量，再按选项内容对应网站当前顺序。乱序返回不会按位置串题。
- 漏题或非法答案会重试一次，仍失败的题保持待解答。格式正确不保证模型知识判断正确。

</details>

### API 兼容性说明

本扩展以 **OpenAI Chat Completions 兼容接口**为对接标准。不同服务商、模型及中转网关对 `system` 消息、结构化输出参数、流式响应和返回字段的实现可能存在差异。因此，声明兼容该接口的服务，仍可能需要依据其接口文档，对请求参数、提示词或响应解析逻辑进行针对性适配。

2.0.3 在 `system` 和 `user` 消息中同时提供答题任务与 JSON 格式要求，以增强输出格式的稳定性。已使用一个实际服务的 `claude-opus-5` 验证单题连接测试和一组 30 道单选、多选、判断题；**该验证仅覆盖当时的服务、模型及配置**，不代表其他 API 已通过兼容性验证。

接入新服务或更换模型、接口版本后，请先运行「测试 AI」。若出现 JSON 不完整、缺少答案字段等错误，应结合具体服务的返回格式排查并适配。扩展仅使用通过格式、题号及选项校验的答案；通过示例题测试也不保证真实题目的答案正确。

## 题库与采集

| 操作 | 结果 |
| --- | --- |
| **导入题库** | 选择本扩展导出的 JSON 文件，兼容旧版题库，自动合并去重。 |
| **导出题库** | 在按钮正上方的菜单选择 Markdown 复习资料，或可再次导入的 JSON。 |
| **清空题库** | 清空本地积累；操作前请先导出需要保留的资料。 |
| **仅采集当前场次题目** | 下载当前场次的独立诊断 JSON，并在浏览器保留一份采集记录；不作答、不调用 AI。 |

<details>
<summary><strong>题库合并与答案保存规则</strong></summary>

- 题型、题干及选项内容相同的题目只保留一条，选项换序不影响去重或匹配，作答时按当前选项重新对应。
- 官方答案优先于 AI 答案，未解答记录不会覆盖已有答案。文件格式错误或同一题存在同等来源的答案冲突时，停止导入并保留原题库。
- 题库沿用网站原有的 `localStorage` 存储，跨场次、跨多次运行累积。
- AI 来源在导出题干末尾标注 `（AI作答）`，原始题干用于匹配。AI 答案即使提交失败也会保留，并记录作答是否核验成功。

</details>

采集文件名为 `场次采集-…json`，用于核对网站真实数据结构，与普通「导出 JSON」的历史题库不同。仅能在对应场次仍可访问时采集当前页面的场次和题目。

## 常见问题

<details>
<summary><strong>为什么没有识别到可作答场次？</strong></summary>

列表只显示接口实际返回、当前开放、尚未交卷且能识别的选择题场次。过期、未开放、已交卷及无法识别的场次不显示。先确认已登录，再点击「刷新场次」。

</details>

<details>
<summary><strong>出现「未找到登录凭证」怎么办？</strong></summary>

登录后刷新考试网页，再使用面板。

</details>

<details>
<summary><strong>更新后仍提示后台是旧版本，怎么办？</strong></summary>

先在扩展管理页重新加载扩展，再刷新考试网页。仅刷新网页不会更新已运行的后台。

</details>

<details>
<summary><strong>更换 AI 服务后，为什么会提示 JSON 格式错误？</strong></summary>

不同服务可能采用不同的输出格式或参数实现，需先使用「测试 AI」验证当前配置，必要时按具体服务适配。参见 [API 兼容性说明](#api-兼容性说明)。

</details>

## 练习与测试的区别

<details>
<summary><strong>展开查看答题策略与网站凭证处理</strong></summary>

已识别的知识练习继续使用原有流程：读取题目，对未答题作答后重新读取 `r_answer`，再校正答案。

测试不会通过随便选择一个选项来探测答案；官方答案缺失时先查题库，再按需调用 AI。场次模式结合接口返回的名称、分组信息、类型及开放时间识别，不只根据页面 URL 判断。

网站登录凭证在请求时从 `sessionStorage` 读取，仅用于原站接口，不发送给 AI 服务。扩展不会调用最终交卷接口。

</details>

模拟测试不等同于真实服务验证，首次配置 AI 后应检查实际调用结果。
